## Instructions

Let's go a little bit deeper into type helpers.

Looking at the tests, we can see that it expects the `Maybe` type helper will returns the thing we're passing in, or `null`, or `undefined`.

```typescript
Expect<Maybe<string>, string | null | undefined>>;
Expect<Maybe<number>, number | null | undefined>>;
Expect<Maybe<boolean>, boolean | null | undefined>>;
Expect<Maybe<null>, null | undefined>>;
```

### Challenge

Your challenge is to write the `Maybe` type helper that will satisfy the tests.

The first step to turning the `Maybe` type into a type helper is to add angle brackets and an argument of `T` which will also be the return value for now:

```tsx
type Maybe<T> = T
```

To help us check our work, we'll create an `Example` type that equals `Maybe` and give it a `string`:

```tsx
type Example = Maybe<string>
```

Now we can update the return type of `Maybe` by adding `T` or `null` or `undefined`:

```tsx
type Maybe<T> = T | null | undefined
```

All of the tests now pass!

The `Maybe` type helper we created is not constrained.

This means that we are able to pass in `null` or `undefined` and get back what we expect since two unions of the same type will be squished together.

The `Maybe` type created here can be useful in several places in your application.
