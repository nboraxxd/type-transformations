## Instructions

As a thought experiment, your challenge is to update `Maybe` to have a constraint that will not allow `null` or `undefined` to be passed in.

You'll know you have it right when `@ts-expect-error` lines in the tests no long show an error:

```tsx
type tests = [
  // @ts-expect-error
  Maybe<null>,
  // @ts-expect-error
  Maybe<undefined>,
]
```

This challenge hones in on an important TypeScript concept!

This challenge might have been a little bit of a mind-bender.

The solution is to find a type that can act as a constraint that is not `null` or `undefined`, but also can represent anything.

We could consider adding `extends` and listing several types:

```tsx
export type Maybe<T extends string | boolean | number> = T | null | undefined
```

This works, but there's a trick that will accomplish the same thing.

Extending an empty object works as a sort of reverse constraint:

```tsx
export type Maybe<T extends {}> = T | null | undefined
```

### Why an Empty Object Works

The empty object value has a specific use in TypeScript, and will represent anything that is not `null` or `undefined`.

TypeScript makes structural comparisons when it checks if things are assignable to each other, and the empty object says that the contract has been met.

Remember, everything in TypeScript is an object, so an empty object represents anything that is not `null` or `undefined`.
