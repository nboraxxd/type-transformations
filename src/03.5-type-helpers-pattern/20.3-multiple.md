## Instructions

Consider this `CreateDataShape` type helper which, as of now, doesn't have any arguments:

```tsx
type CreateDataShape = {
  data: unknown
  error: unknown
}
```

From the tests we can see that we should get back an object with `data` being the first type passed in, and `error` the second.

For example, `CreateDataShape<string, TypeError>` should return this:

```tsx
{
  data: string
  error: TypeError
}
```

### Challenge

Your challenge is to make the `CreateDataShape` type helper work by devising a way to provide multiple type arguments.

## Solutions

<details>
<summary>Click For Solution</summary>

The solution here is nice and simple:

```tsx
type CreateDataShape<TData, TError> = {
  data: TData
  error: TError
}
```

Using the comma operator between `TData` and `TError` allows us to specify multiple generics.

I haven't found a hard limit on the number of generics that can be added, and I've seen a lot!

You can compose a lot of generics together similarly to how you can pass many arguments to a function

</details>
