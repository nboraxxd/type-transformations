## Instructions

This `AddRoutePrefix` type helper that has already been scaffolded for us.

It takes in `TRoute` then puts it into a string literal that adds a `/` to the beginning:

```typescript
type AddRoutePrefix<TRoute> = `/${TRoute}`
```

This is passing most of our tests, but not all.

Using `@ts-expect-error` tells the tests we expect an error when passing a boolean or number to the `AddRoutePrefix` type helper.

### Challenge

Your challenge is to work out what is causing the error, and solve it by putting some constraints on what can be passed in.

The solution is to update `AddRoutePrefix` so we can only pass in a string.

To do this, we'll add `extends string` to the type helper to tell it that `TRoute` must be a string:

```tsx
type AddRoutePrefix<TRoute extends string> = `/${TRoute}`
```

### More on Constraints

As seen in the introduction to the exercise, for most things we don't need to add `extends` because TypeScript is able to infer the type of what we pass in. However, if we know that later we're going to need to do string-specific operations, it's important to add constraints.

If you don't pass in a type constraint, TypeScript will assume that `TRoute` is unknown. This means that it doesn't have any properties associated with it which puts us a little bit closer to danger.

For the sake of experimenting, we can update `AddRoutePrefix` to extend every type from the tests and they will all pass:

```tsx
type AddRoutePrefix<TRoute extends string | number | bigint | boolean | null | undefined> = `/${TRoute}`
```

However, adding an object to the extends will cause an error because `{wow: true}` is not assignable to that type.

Many type helpers add their own constraints, including built-in ones like `Record`.

Let's create an example `Record` then use CMD + click in VS Code to see its source code:

```tsx
type Yeah = Record<string, string>
```

In the source for `Record` we can see that it extends `keyof any`:

```tsx
type Record<K extends keyof any, T>
```

We'll get to what this specifically means later, but for now you can see how `extends` allows us to set different constraints on our type helpers.
