## Instructions

Consider this `GetParametersAndReturnType` type helper that is used to extract the parameters and return types of `T`:

```tsx
type GetParametersAndReturnType<T> = {
  params: Parameters<T>
  returnValue: ReturnType<T>
}
```

There are a few test scenarios, all of which are passing:

```tsx
  Expect<
    Equal<
      GetParametersAndReturnType<() => string>,
      { params: []; returnValue: string }
    >
  >,
  Expect<
    Equal<
      GetParametersAndReturnType<(s: string) => void>,
      { params: [string]; returnValue: void }
    >
  >,
  Expect<
    Equal<
      GetParametersAndReturnType<(n: number, b: boolean) => number>,
      { params: [number, boolean]; returnValue: number }
    >
  >,
```

The problem comes when hovering over `T` in `GetParametersAndReturnType`:

```
Type 'T' does not satisfy the constraint '(...args: any) => any'
```

## Solutions

<details>
<summary>Click For Solution</summary>

The solution is to use the `extends` keyword to constrain `T`. In this case, we need `T` to be typed as a function with a return type of `any`:

```tsx
type GetParametersAndReturnType<T extends () => any> = {}
```

With this change in place, we no longer have an error in our type helper, but we do with our tests:

```tsx
 Expect<
    Equal<
      GetParametersAndReturnType<(s: string) => void>,
      { params: [string]; returnValue: void }
    >
  >,
```

For example, the above test complains that `(s: string) => void` does not satisfy the constraint `() => any`.

The tests have different parameter shapes, we can't hardcode the type helper to look for strings.

In order to make our type helper work, we will update `GetParametersAndReturnType` to use the rest parameter with `args` and type it as `any`:

```tsx
type GetParametersAndReturnType<T extends (...args: any) => any> = {}
```

This means that we can accept any number of arguments, including zero, and it will return a function or anything from that function.

By copying this constraint, we've matched up what we expect to pass into this type helper based on what we want to use it for.

This is a nice bit of syntax to remember, as it allows us to use functions as constraints in our type helpers.

</details>
